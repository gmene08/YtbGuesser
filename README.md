YouTube Guesser is a real-time multiplayer game where players compete to guess the exact view count of random YouTube videos. Built with a distributed architecture to handle high-frequency real-time events and persistent state synchronization.

## 🏗️ System Architecture

The project is divided into three main components, following a **Fast Path / Slow Path** architectural pattern:

1. **Frontend (Angular):** Responsive UI built with Signals and TailwindCSS. Manages the YouTube IFrame API and complex local state (timers, leaderboards, video synchronization).
2. **Core Backend (Java / Spring Boot):** The "Slow Path" and Source of Truth. Handles persistent data (MySQL), user authentication, lobby management, and the YouTube API integrations.
3. **Game Engine (Node.js / Express / Socket.io):** The "Fast Path". A dedicated microservice to handle high-frequency, volatile in-game events (timers, live guesses, chat) via WebSockets without overloading the main Java backend.

## 🚀 Key Engineering Highlights

### ⚡ Real-Time State & Synchronization
* **Decoupled Architecture:** Lobby management is handled by Java via HTTP, while active gameplay is transferred to the Node.js Engine via WebSockets. This ensures ultra-low latency for game mechanics.
* **Custom Video Sync Algorithm:** Implemented a robust synchronization system that calculates elapsed round time versus absolute server time. If a player disconnects and reconnects mid-round, the video resumes at the exact millisecond it should, perfectly synced with other players.
* **Resilience & Disconnect Handling:** Graceful handling of edge cases (e.g., users leaving mid-round, accidental page reloads). The system uses Delta Updates to inform the frontend of player drops instantly, recalculating the leaderboard and round requirements dynamically.

### 🛡️ Security & Authentication
* **Stateless Auth with Cookies:** JWT tokens are generated by the Spring Boot backend and securely transmitted via **HttpOnly cookies**. This protects the application against XSS attacks, as tokens are never exposed to the frontend's JavaScript/LocalStorage.

### 🗄️ Caching & Memory Management
* **Redis Integration:** Used AWS ElastiCache (Redis) to handle volatile game data such as real-time activity logs and chat history. This prevents database bottlenecks and allows instant retrieval for reconnecting players.

### 🔄 Smart YouTube API Quota Management
* Designed a highly optimized background job (CRON) in Spring Boot to keep the video database fresh and view counts accurate. 
* Instead of burning the daily YouTube API quota by re-searching videos, the system batches 50 existing video IDs per request to the `/videos` endpoint, consuming only 1% of the quota while updating thousands of records daily.

## ☁️ Infrastructure & Deployment

The application is containerized and deployed on **Amazon Web Services (AWS)**:
* **Compute:** AWS EC2 instance running Docker Compose (Frontend + Node.js Engine + Nginx reverse proxy).
* **Database:** Amazon Aurora RDS (MySQL) for high availability and automated backups of persistent data.
* **Cache:** Amazon ElastiCache (Redis) for real-time log management and session handling.

## 🛠️ How to Run Locally

To ensure smooth development and bypass local HTTPS/CORS restrictions required by the YouTube IFrame API, the Angular frontend is run separately from the backend containers in the local environment.

**1. Start the Backend Infrastructure (Docker)**
Ensure Docker is running, then spin up the Java Backend, Node.js Engine, DB MySql and Redis cache:
```bash
git clone https://github.com/gmene08/YtbGuesser.git
cd YtbGuesser

# Configure your .env files (Database credentials, YouTube API Key, JWT Secret)
docker-compose up -d backend engine redis db
```
**2. Start the Frontend (Angular CLI)**
In a new terminal window, serve the Angular application:
```bash
cd video-guesser-ui
npm install
ng serve
